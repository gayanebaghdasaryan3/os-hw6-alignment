#include <stdio.h>

int main() {
    int a = 42;
    char b = 'G';
    double c = 3.14;
    short d = 3;

    printf("Size of int: %zu bytes\n", sizeof(a));
    printf("Address of int: %p\n", (void *)&a);

    printf("Size of char: %zu byte\n", sizeof(b));
    printf("Address of char: %p\n", (void *)&b);

    printf("Size of double: %zu bytes\n", sizeof(c));
    printf("Address of double: %p\n", (void *)&c);

    printf("Size of short: %zu bytes\n", sizeof(d));
    printf("Address of short: %p\n", (void *)&d);

    return 0;
}

Size of short: 2 bytes

Explanation:
After compiling and running the program, I found that int occupies 4 bytes, char occupies 1 byte, double occupies 8 bytes, and short occupies 2 bytes. 
The addresses showed that the variables were not stored in the order in which they were declared. The addresses did not necessarily follow the order in which the variables were declared, since the compiler determines how local variables are arranged in memory. 
The addresses also demonstrate alignment. The address of short is divisible by 2, the address of int is divisible by 4, and the address of double is divisible by 8. This means that these variables are stored at addresses aligned to their respective sizes. The char variable occupies one byte and does not require a larger alignment boundary.

#include <stdio.h>

struct Original {
    char a;
    int b;
    double c;
};

struct Reordered {
    double c;
    int b;
    char a;
};

int main() {
    struct Original first;
    struct Reordered second;

    printf("Original struct:\n");
    printf("Size of struct: %zu bytes\n", sizeof(first));
    printf("Address of a: %p\n", (void *)&first.a);
    printf("Address of b: %p\n", (void *)&first.b);
    printf("Address of c: %p\n", (void *)&first.c);

    printf("\nReordered struct:\n");
    printf("Size of struct: %zu bytes\n", sizeof(second));
    printf("Address of c: %p\n", (void *)&second.c);
    printf("Address of b: %p\n", (void *)&second.b);
    printf("Address of a: %p\n", (void *)&second.a);

    return 0;

Since char occupies 1 byte and int requires 4-byte alignment on this system, 3 bytes of padding are added between a and b. The double starts at an address aligned to 8 bytes, and the int starts at an address aligned to 4 bytes. Since a only requires 1-byte alignment, no padding is needed between the fields. It also ensures that the struct's total size is a multiple of its alignment, so that the members of an array of such structs remain properly aligned.

#include <stdio.h>

struct NormalStruct {
    char a;
    int b;
    double c;
};

#pragma pack(1)
struct PackedStruct1 {
    char a;
    int b;
    double c;
};

#pragma pack(2)
struct PackedStruct2 {
    char a;
    int b;
    double c;
};

#pragma pack(4)
struct PackedStruct4 {
    char a;
    int b;
    double c;
};

int main() {
    struct NormalStruct normal;
    struct PackedStruct1 packed1;
    struct PackedStruct2 packed2;
    struct PackedStruct4 packed4;

    printf("Size: %lu bytes\n", sizeof(normal));
    printf("Address of a: %p\n", (void *)&normal.a);

In the normal struct, char a is stored at 0x7fff7f3a85d0, int b at 0x7fff7f3a85d4, and double c at 0x7fff7f3a85d8. Since char occupies 1 byte and int requires 4-byte alignment on this system, 3 bytes of padding are inserted between a and b. The double field starts at an address aligned to 8 bytes.

With #pragma pack(1), the struct occupies only 13 bytes. The address of a is 0x7fff7f3a85b5, b is at 0x7fff7f3a85b6, and c is at 0x7fff7f3a85ba. The fields are stored directly next to each other without padding, so the total size is 1 + 4 + 8 = 13 bytes.

Changing the packing value affects how much padding is inserted and therefore changes the total size of the struct. Smaller packing values can reduce memory usage, but they may also lead to less efficient memory access because some fields are not naturally aligned.
